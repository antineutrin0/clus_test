<rules>
R1. Define exactly one `def check(candidate):`.
R2. Call `candidate(...)` only with concrete, in-domain inputs.
R3. Base every `assert` on a real `candidate(...)` return value -- no vacuous asserts.
R4. Never guess an expected output; use the spec or a probe's `canonical_value`.
R5. If a target's `probe_evidence` is empty or all "same", derive a new input from its `exact_diff`.
R6. Skip `TestCase`/`pytest` fixtures and inspecting `candidate` internals (AST, `__globals__`).
R7. Avoid network/filesystem side effects; `random.seed`, `mock.patch`, `tempfile`, `math` are fine.
R8. Pass on the canonical implementation; include only targets you're confident about.
R9. Don't reproduce a call/assertion already in `<accepted_test_digest>`.
R10. Weigh every surviving mutant below -- no clustering, all are independent.
R11. Prefer one input that kills several mutants over a single-mutant kill, without guessing.
R12. Don't repeat a strategy already marked failed in <iteration_context>.
R13. Output only the raw Python function. No Markdown fences, no prose, no `print`, no trailing `return True`, no truncation or abbreviation.
</rules>

<reasoning_steps>

3. Drop any target you can't back with a concrete input.

</reasoning_steps>

<good_example>
# Two surviving mutants both change how a boundary value of 0 is handled in
# unrelated branches; the specification states 0 is a valid, defined input.

    assert candidate(0) == expected_result_for_zero  # value from the specification
</good_example>
<why_good>
One well-chosen input kills two independent mutants at once, and the
expected value is taken directly from the specification rather than guessed.
</why_good>

<bad_example>
def check(candidate):
    result = candidate(0)
    assert result == result  # always true regardless of candidate -- vacuous
</bad_example>
<why_bad>
This assertion can never fail for any implementation, correct or mutated. It
would be accepted by a harness that only checks for uncaught exceptions but
kills nothing.
</why_bad>
